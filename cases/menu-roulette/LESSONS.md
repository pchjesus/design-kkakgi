# SIDE-001 · 뭐먹지? — 디자인 비교와 교훈

> 일자: 2026-10-17 · 상태: 사용자 승인 디자인 채택, 미검증 항목은 별도 표기
> 서비스: [실행 사이트](https://pchjesus.github.io/menu-roulette/) · [소스](https://github.com/pchjesus/menu-roulette)
> 기준 지침: Universal Visual Design UI/UX Guidelines v1.2 (DRAFT; 개정 승인 아님)

## 1. 실험의 맥락

- 서비스는 점메추·저메추·카페 메뉴를 630개 목록에서 추천하는 **실사용 도구**다.
- 처음에는 원형 룰렛을 고려했으나 이후 사용자 요구로 **1~3칸 슬롯머신**으로 변경했다.
- 목적은 조작하기 쉬운 메뉴 추천이므로 기계 오브젝트, 선택 패널, 결과를 우선하고 불필요한 선행 정보는 줄인다.
- 추천 로직: 조건에 맞는 전체 후보 메뉴를 먼저 균등 비복원 추첨하고, 슬롯 회전은 결과와 독립적으로 연출한다.

## 2. 디자인 단계별 평가 (사용자 피드백과 구현을 구분)

| 단계 | 주요 변경 | 사용자 평가·관찰 | 채택 |
|---|---|---|---|
| A. 원본 v0.1.4 | 아이보리·차콜·오렌지, 슬롯/설정 2열 | 따뜻한 배경과 기계가 잘 어울린다는 비교 평가 | 따뜻한 색채 보존 |
| B. Object-first (실험01) | 청백색 배경, 슬롯 음영 강화, 조작 패널 간소화 | **원본이 낫다**. 슬롯과 배경의 색감이 어울리지 않음 | 청백색 폐기 |
| C. Warm-centered (실험02) | 기존 따뜻한 색감 + 최대 1000px 중앙 배치 + 1.3:.82 패널 비율 | 새 레이아웃 자체와 슬롯/조작 패널의 크기 비율, 가운데 맞춤이 좋다는 평가 | 채택 |
| D. 마감 패치 | 두 패널 하단 정렬, 사용법 + 회전 및 슬라이드 | 기존 상태의 높이 차이를 지적하고 마감 패치 요청, 이어서 긍정 평가 | 채택·정식화 |

**핵심:** 실험01은 전체적으로 선호되지 않았지만, 슬롯과 패널의 비율 및 정렬은 개선된 부분으로 분리해 활용했다.

## 3. 확인된 사용자 선호 / 해석 / 일반화의 한계

### 사용자가 실제로 말한 것
- 이전 따뜻한 색감이 청백색 실험보다 낫고, 슬롯머신과 배경의 조화가 중요하다.
- 파란색은 일부 바다 음식 계열 외에 음식 서비스와 연결이 약해 보인다. 이는 **사용자의 이번 서비스 맥락에 대한 판단**이며 색채 일반 법칙이 아니다.
- 기존 실험의 새로운 레이아웃과 슬롯·조작 패널 비율은 괜찮다.
- 다른 디자인에서도 좌측 정렬의 습관적 사용을 느꼈고, 이 작은 앱에서는 중앙 배치도 자연스럽다고 본다.
- 패널의 아래 높이가 달라 시각적으로 거슬리며, 설명창 아이콘이 +에서 ×로 돌아가며 내용이 내려오는 표현을 원한다.

### 프로젝트에 적용한 설계 해석
- **색조 맥락:** 기존 색이 오래된 습관처럼 보인다는 이유만으로 바꾸지 않는다. 핵심 오브젝트와의 색온도·대비·연관성을 먼저 설명할 수 있어야 한다.
- **사용 규모에 맞는 레이아웃:** 넓은 화면 활용 자체가 완성도를 보장하지 않는다. 단일 작업형 작은 도구는 중앙 집중이 잘 맞을 수 있다.
- **부분 채택:** 실험안에 실패한 색상과 성공한 비율이 동시에 존재할 수 있다. 각각 따로 판단한다.
- **표현적 오브젝트:** 슬롯의 입체감·레버·감속 등은 기능과 즐거움을 함께 만드는 시각 언어다. 무조건 평면화하지 않는다.
- **미세 정렬/피드백:** 하단 정렬, 아이콘 회전, 펼침·접힘 모션이 화면의 완성도를 좌우할 수 있다.
- **기능 보존:** 스타일 변경이 실제 추첨 공정성, 슬롯 정지 결과, 모달 탐색 및 로컬 저장의 동작을 해치지 않도록 분리한다.

### 아직 보편화할 수 없는 것
- 파랑/차가운 배경이 모든 식품·요식 UI에 부적합하다는 주장.
- 중앙 정렬이 모든 도구에서 왼쪽 정렬보다 낫다는 주장.
- 특정 사용자 1인의 평가가 전체 이용자 사용성·전환율 향상을 증명한다는 주장.
- 한 차례 실험에서 나타난 색채 문제의 정확한 원인이 배경 온도 하나뿐이라는 단정(레이아웃·폰트·표면도 일부 함께 변경).

## 4. 앞으로의 디자인 검증 방식에 대한 제안

1. 현재 디자인의 강점을 먼저 지정한 뒤 바꿀 축을 최소화한다.
2. 색채와 레이아웃 실험은 가급적 서로 분리해 원인을 추적한다.
3. 사용자 평가에서는 **미관 / 소재와 목적의 적합성 / 사용성 / 구현 정확성**을 별도로 기록한다.
4. 사용자가 좋아한 요소는 보존하되 범용 지침의 강제 규칙으로 자동 변경하지 않는다.
5. 작업형 UI에서는 클릭 이후 결과·상태와 키보드·동작 축소를 실제로 점검한다.

## 5. 구현·검증 상태

- 앱은 `pchjesus/menu-roulette`의 `main` v0.1.5가 유일한 현행 코드 원본이다.
- GitHub 구조 및 HTML/CSS/JS 참조 확인: 정적 검사 대상.
- 설명창 클릭·연속 열기/닫기·동작 축소: 이전 실험 단계의 모의 테스트 기록이 있으며 정식 배포 브라우저 검사와 구별한다.
- 이전 v0.1.4의 자동 테스트 20개 통과 기록은 과거 기준이다.
- **NOT RUN:** v0.1.5 신규 브라우저 실측/모바일 실기기/스마트폰 스크린리더/시각적 선호도 비교 A/B 테스트.
- 이미지·스크린샷 원본은 본 저장소에 업로드하지 않는다.

## 6. 다음 단계

- 디자인은 당분간 v0.1.5를 유지하며 실제 사용 중 불편이 확인될 때만 부분 수정한다.
- 메뉴 데이터/추첨/카탈로그는 별도 저장소에서 개발한다. 디자인 깎기에는 **확인된 피드백과 설계 의사결정**만 기록한다.
- v1.2 디자인 지침은 DRAFT를 유지하며 이 사례만으로 지침을 확대하지 않는다.
