# UI/UX 적용 기록 — SAI v0.2

## 디자인 목표

독자가 첫 화면에서 **“이야기의 질문을 논문으로 살펴보는 블로그”**라는 목적을 이해하고, 한 번의 명확한 선택으로 첫 글을 읽을 수 있도록 한다. 읽기 화면에서는 독자가 **연구 결과/작품 해석/한계**를 혼동하지 않도록 한다.

## 첨부 표준 1.0 → 블로그 적용

| 원칙 | 구현 방향 | 확인 포인트 |
|---|---|---|
| Purpose first | 소개 문장, 1차 CTA `첫 이야기 읽기` | 첫 클릭으로 글 상세 페이지 진입 |
| One primary task per view | 홈: 첫 이야기 읽기 / 글: 본문 읽기 / 작성: 저장하기 | 경쟁하는 큰 CTA 최소화 |
| Progressive disclosure | 목록에서는 핵심 소개만, 상세 페이지에서 방법·근거·한계·참고문헌 | 한계·예시임을 상세에서 명확히 제시 |
| Information hierarchy | Hero → 읽기 방식 → 추천 글 → 목록 → 편집 철학 | 제목·상태·메타 정보 정돈 |
| Honest data | 예시 글·교육용 해설 표시, 근거 유형·범위·해석/한계 구분 | 동물실험을 인간 임상 적용으로 오해하지 않도록 |
| State independence | 검색·필터 상태와 작성(미저장/저장된 글), 북마크 분리 | 작성 취소 시 원글 유지, 수정 저장 시 일관 반영 |
| Accessibility | 키보드 동작, skip link, 44px 이상 주요 버튼, ARIA, 포커스 복귀 | 320/360/390/768/1024 등 확인 |
| Reduced motion | CSS 미디어 쿼리 대응 | 모션 설정 `reduce`에서 smooth scroll 금지 |
| Testable hypothesis | 시연·자동화 테스트 결과와 사용자 사용성 검증 분리 | 실제 사용자 유효성 주장 금지 |

## 상태 전환

- 홈 목록 → 글 상세(`#post/{id}`) → 목록(`#library`) / 저장한 글(`#saved`)
- 검색·필터 변경은 저장된 글 데이터 자체를 수정하지 않음
- 신규 작성 / 수정 다이얼로그 → **저장** 시에만 localStorage 커밋 → 상세 보기
- 다이얼로그 닫기 → 미저장 변경 시 확인 → 미커밋 편집은 폐기
- 북마크·테마는 독립적으로 저장하며 글 본문 데이터를 수정하지 않음
- 브라우저 `back`/`forward` 및 새로고침 시 해시 URL에 따라 화면 복원

## 의도적으로 채택하지 않은 사항

- 교육 시뮬레이터의 A/B/C 학습 실습 탭과 실제 기기 재현, 상태·시간 엔진은 본 블로그와 무관함
- 임상 검증이나 교육 효과를 디자인만으로 주장하지 않음
- 색상은 시뮬레이터 제품의 고유 팔레트를 복제하지 않고, `근거=녹색`과 `서사=갈색` 등 의미를 구분하는 자체 토큰 사용

## 후속 과제

1. 실제 독자(처음 온 사람)에게 블로그 목적과 시작 행동 확인
2. APA 서지 자동 검증(Crossref/DOI), 원문 수준의 연구설계 템플릿
3. 로그인/DB/업로드/백업, 운영자 콘텐츠 승인 및 공개 게시
4. 모바일 실기기, 보조기술(screen reader), 브라우저별 저장 동작 확인
