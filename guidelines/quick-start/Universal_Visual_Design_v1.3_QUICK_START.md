# Universal Visual Design v1.3 — 빠른 실행 카드 (Approved)

> **2026-10-21 사용자 승인 / 현행 v1.3 보조 카드** · 전체 기준: [v1.3 승인 지침](../universal/Universal_Visual_Design_UI_UX_Guidelines_v1.3.md). **카드는 원문을 대체하지 않고, 외부 레퍼런스는 필요할 때만 로드한다.**

## 1. 신규 설계 · 큰 변경: 이 순서만 우선

1. **무엇/누가/왜:** 소재·대상 역할·사용 장면·1차 행동/성공을 한 문장으로 정의.
2. **정보와 상태:** 함께 봐야 할 정보, 미확정·결측·검토/승인·저장, 역할별 노출 범위를 먼저 정한다.
3. **구조 선택:** 신규/대형 작업이면 다른 레이아웃 **2안 정도** 비교. 탐색/선택과 상세 정보의 너비는 각 과업에 맞춘다. 단순 패치에는 생략.
4. **필요한 레퍼런스만:** 웹 IA·여정 → [KRDS](../../references/krds/README.md), 플랫폼 컨트롤·계층 → [Apple](../../references/apple/README.md), 크기 적응형 탐색·앱 컨트롤 → [Material 3](../../references/material3/README.md). 복합 서비스라면 [통합 선택 지도](../../references/DESIGN_SYSTEM_SELECTION.md).
5. **표현 선택:** 실제 소재·빛·사용 환경을 고려해 색채를 정하고, 브랜드명이 반복되는 로고/제목 서체 관계와 **의도한 행 나눔**을 실제 화면에서 확인한다. 회녹색/베이지/감성 카피/큰 카드/유리 효과를 자동 반복하지 않는다.
6. **보존·검증:** 이미 좋다고 승인한 요소·기능·URL·저장 상태를 보호하고 위험도에 맞춰 실제 화면/상태/회귀를 테스트.

## 2. 화면 유형 분기

| 사용자 작업 | 먼저 검토할 구성 |
|---|---|
| 방문·홍보·브랜드 감상 | 콘텐츠/제품 중심 → 세부 탐색 → 필요시 구매/행동 |
| 글·정보 읽기 | 짧은 요약 → 본문/출처 → 관련 콘텐츠 |
| 작은 단일 도구 | 중앙 집중형 조작·결과; 넓은 좌우 패널이 불필요할 수 있음 |
| 고밀도 업무 | 목록/필터/상태·근거·편집을 동시 파악할 수 있는 구조 |
| 환자·일반 사용자 | 오늘 할 일·확인된 안내·일정·문의처 우선, 역할별 정보·상태 엄격 구분 |

## 3. 변경 위험도에 따라

| L — 국소 표현 | M — 구조/동작 | H — 데이터·권한·안전 |
|---|---|---|
| 인접 정렬·읽기·대비·화면 폭 확인 | 정상/빈/오류·키보드·모바일·저장·관련 회귀 | 구버전 데이터 픽스처/이전·롤백, 승인·공개·복구 및 관련 전문 검증 |

**MUST:** 필요한 검증을 토큰 절약 때문에 생략하지 않는다. 문서 검토는 실제 브라우저 테스트가 아니다.

## 4. 결과 보고 4칸

- **선택 이유:** 왜 이 구조/서체/색/컴포넌트가 목적에 맞는가?
- **보존과 변화:** 기존 강점, 바꾼 요소, 거절한 대안.
- **증거:** 공식 가이드 / Figma 이름 / 사용자 선호 / 프로젝트 초안 / 실제 테스트를 구별. A/B 버튼을 눌렀을 때 **해당 화면이 실제 표시되는지** 먼저 확인.
- **검증 상태:** `PASS / FAIL / NOT RUN / N/A`; 저장·승인·공개는 실제 상태만 표시.

**마지막 질문:** 다른 업종/제품에서도 이름만 바꾸면 똑같은 화면인가? 그렇다면 해당 사용자 과업과 소재의 특징부터 다시 살핀다.
