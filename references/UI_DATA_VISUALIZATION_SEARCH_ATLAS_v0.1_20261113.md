## 2. SRC-25 — 시각화 9종을 '무엇을 알아야 하는가'로 구분

| 번호 · 원문 | 데이터 관계와 적합 과업 [AI-HYP] | 정적 예시에서 확인되는 것 [CAP] | 해석 위험·검증 질문 |
|---|---|---|---|
| **01 Bar chart / 막대 그래프** | 범주별 양·규모·순위 비교. 예: 병동별 환자 수 | 높이가 다른 막대들 | 길이로 크기를 비교한다면 수량 축의 **0 기준**이 중요. 축 단절·비동일 간격·단위 누락 주의 |
| **02 Line chart / 선 그래프** | 시간 또는 연속형 축에 따른 추세. 예: 시간별 혈압 | 상승하는 꺾은선과 음영 | 축 범위·시간 간격·결측값·관측 시점 명시. 선그래프는 맥락상 0이 아닌 Y축도 가능하지만 변화의 인상이 왜곡되지 않아야 함 |
| **03 Donut chart / 도넛 차트** | **부분 대 전체** 구성. 예: 유형별 지출 비중 | 원형 링에 '62%' 수치 | **구성비인지 진행률인지** 맥락으로 확인. 복수 구성 요소·비슷한 비율의 정밀 비교에는 막대/표가 유리할 수 있음 |
| **04 Sparkline / 스파크라인** | 표·리스트 안에서 미세한 추세를 압축. 예: 종목별 최근 변화 | 가격·증감률 옆 작은 선 2개 | 축·기간·크기·시작점·값을 생략하기 쉬우므로 단독 해석 금지. 방향 이외에 정확한 값/기간도 제공 |
| **05 Gauge / 게이지** | 범위 내 현재값과 목표/허용범위의 관계. 예: 기준 대비 점수 | 반원형 호와 바늘 | 단일 수치에는 숫자 카드가 더 쉬울 수 있음. 최소·최대·정상/위험 구간·방향을 명시하지 않으면 장식에 그침 |
| **06 Progress ring / 진행 링** | 완료 목표를 분모로 삼는 작업 진행 상태 | '80%'와 '5건 중 4건' | **분모·완료 정의·상태 정확성** 필수. 불확정 대기를 가짜 퍼센트로 만들지 않기. Donut과 형태만 같고 의미는 다를 수 있음 |
| **07 Heatmap / 히트맵** | 시공간·요일/시간대·매트릭스의 값 밀도/패턴 | 진한 파랑부터 옅은 칸까지 격자 | 색만으로 값 구분 금지. 범례, 규모 기준(합계/비율), 색각·고대비·수치 대안, 결측·0 구별 |
| **08 KPI card / KPI 카드** | 중요한 개별 수치·기준 대비 변화의 즉시 확인 | '4.8백만'·'312건'과 작은 변화 표시 | **차트가 아니라 정보 요약 단위**. 단위/기간/기준·모집단·업데이트 시간 누락 시 해석 오류 |
| **09 Stacked bar / 누적 막대** | 전체 크기와 범주별 구성의 동시 표현 | 여러 색의 막대가 세로로 쌓임 | 전체량과 각 부분 비교의 정확성을 구별. 비율을 비교한다면 **100% 누적**을 별도 고려. 조각이 많으면 비교 불리 |

### 서로 혼동하기 쉬운 의미 차이

- **Donut ≠ Progress ring:** 원형 링이라는 시각적 유사성만으로 똑같이 쓰지 않는다. ‘62%가 A유형’과 ‘진행률 62%’는 분모 및 사용자의 다음 행동이 다르다.
- **Gauge ≠ Progress ring:** 게이지는 상태/수준의 범위 내 위치, 진행 링은 완료를 향한 경과를 표현하기에 적합한 경우가 많다. 사용자 인터페이스에서 예외가 있을 수 있어 **데이터 계약이 우선**한다.
- **Sparkline ≠ full line chart:** 둘 다 선이지만, 스파크라인은 주변 숫자/표와 결합한 요약 요소다. 상세 해석에는 별도의 값과 그래프가 필요하다.
- **Stacked bar ≠ 일반 bar:** 전체 수치와 구성 비율 중 무엇을 비교할지 구분. 누적 막대의 가운데 조각은 공통 기준선이 없어 정밀 비교가 어렵다.
- **KPI card ≠ 차트:** 숫자와 설명을 가장 먼저 확인해야 하는 업무라면 차트로 만들 필요가 없다.

**[EXTERNAL / FT]** Financial Times의 *Visual Vocabulary*는 차트 이름보다 **편차(Deviation), 상관(Correlation), 순위(Ranking), 분포(Distribution), 시간 변화(Change over time), 규모(Magnitude), 부분-전체(Part-to-whole), 공간(Spatial), 흐름(Flow)** 같은 데이터 관계를 먼저 고르게 안내한다. 해당 목록은 완전한 목록이나 자동 정답 선택기가 아니다. [FT Chart Doctor](https://github.com/Financial-Times/chart-doctor/blob/main/visual-vocabulary/README.md).

| **06 Sort / 정렬** | 결과 **순서만 바꿈** | 추천순·낮은 가격순·리뷰 많은순 | 정렬 기준·동률 처리·결측값·실시간 변경·페이지 이동 시 상태 유지 |
| **07 Highlight / 검색어 강조** | 결과 내 일치 부분을 알아보기 쉽게 표시 | 일치하는 문자에 파란 강조 | 강조할 정확한 문자열·부분 일치·대소문자/한글 정규화, 색에만 의존하지 않는 구별. 검색 결과의 일부를 생략해 오인 유도하지 않기 |
| **08 No results / 결과 없음** | 검색어·필터 조합에 결과가 없을 때의 회복 | '검색 결과가 없어요'와 대체 검색어 | **검색 결과 0건 ≠ 필터 0건 ≠ 네트워크 오류 ≠ 권한 없음**. 조건 완화·오타 수정·전체 보기 등 다음 행동 |
| **09 Scope tabs / 검색 범위 탭** | 전체·상품·브랜드·리뷰 등 자료 유형 이동 | 전체/상품/브랜드/리뷰 탭 | 범위 변경 시 검색어·필터·정렬·스크롤 유지/초기화 정책이 일관되고 접근 가능해야 함 |

### 흐름으로 보면 분류가 분명해진다

**검색어 입력(01) → 입력 보조(02·03·04) → 검색 실행 → 범위 선택·결과 제어(05·06·09) → 일치 표현(07) → 결과 없음·오류·복구(08)**

- **Filter와 Sort는 서로 다르다:** 필터는 어떤 결과가 포함되는가, 정렬은 포함된 결과가 어떤 순서로 보이는가를 다룬다.
- **Scope tabs와 Filter도 다르다:** 자료의 출처/종류를 전환하는 것과 같은 종류의 결과를 세부 조건으로 좁히는 것은 의미상 구별할 수 있다. 실제 제품에서 결합될 수 있다.
- **Auto-suggestion과 자동 실행 검색은 다르다:** 추천 후보를 보여주거나 검색어를 완성하는 것과, 매 키 입력마다 서버 결과를 갱신하는 것은 네트워크 및 선택 계약이 다르다.
- **결과 없음은 그 자체로 실패가 아님:** 빈 결과 자체는 정상 응답일 수 있고, 필터가 지나치게 제한적이라면 그 조건을 분명히 보여주어야 한다.

**[OFFICIAL / W3C]** [WAI-ARIA Combobox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)은 입력형 콤보박스와 팝업의 키보드 동작(예: Down Arrow, Enter, Escape) 및 `aria-controls`·`aria-autocomplete` 등의 접근성 의미를 다룬다. 단, **검색어 제안에 콤보박스를 채택한 구현에 적용**되는 것이지 모든 검색창에 무조건 같은 ARIA 속성을 부여하라는 뜻은 아니다.

**활용 후보 [AI-HYP]:** 포트폴리오 비교는 **검색+필터+정렬+테이블+스파크라인/상세 선형 차트**, 의료 업무는 **목록 검색+중요도 표시+KPI(단위·시점 명시)**, 학습 시뮬레이터는 **값·시간 관계에 맞는 차트/진행 상태** 등을 비교 후보로 검토한다. **기존 앱 기능이나 임상적 판단 규칙을 이 노트만으로 변경하지 않는다.**

### 실무 판단 질문

1. 사용자가 알고 싶은 것이 **비교 / 추세 / 구성 / 진행 / 범위 내 수준 / 핵심 수치** 중 무엇인가?
2. 차트를 뺀 간결한 **수치+단위+설명**이 더 좋은가?
3. 색·축·기준·결측·기간·정렬 기준을 **독립적으로 해석할 수 있는가**?
4. 검색 범위·필터·정렬이 어떤 순서로 적용되고, 뒤로 가기 후에도 의도대로 **복원되는가**?
5. 결과 0건·데이터 로딩 실패·정보 없음·권한 거절을 구별하는가?
6. 임상/금융 수치는 **정확한 원자료·계산 정의·단위·업데이트 시점**에 접근할 수 있는가?
