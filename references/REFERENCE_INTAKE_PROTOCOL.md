# 새 레퍼런스 인입·분석·GitHub 등록 프로토콜 v0.1

> 2026-11-16. 사용자의 지속 운영 요청: **레퍼런스를 가져오면 먼저 분석하고 등록**. 심화 논문 조사·실험은 필요할 때만 후속 수행한다. 본 프로토콜은 승인된 범용 v1.3, 제품 코드, 배포를 변경하지 않는다.

## 등록 6단계

1. **자료 직접 확인:** 화면·PDF·URL에서 실제 확인되는 것을 관찰. 읽을 수 없는 글씨·움직임·효과는 확인했다고 쓰지 않는다.
2. **분류와 중복 조회:** 기존 Visual(REF/COLOR/STYLE/ORIGIN), Patterns(SRC), Foundations(FOUND), Systems, 실험(LAB) 계열 중 분류. 비슷한 주제는 교차링크. 기존 ID 재번호 금지.
3. **표준 분석:** 목적/사용자/맥락, 타이포·색·레이아웃·이미지·재료·광원·정보 위계, 좋은 점, 불리한 조건, 기존 취향 일치/새 발견/충돌.
4. **근거 분리:** [USER] 사용자가 직접 평가, [OBS] 실제 관찰, [SOURCE] 출처의 주장, [OFFICIAL] 공식 확인, [AI-HYP] 추론, [NOT RUN] 미검증.
5. **기록/색인:** 적절한 아틀라스 문서 작성 또는 증보, [통합 허브](ATLAS_HOME.md) 및 [기존 레퍼런스 목록](README.md)에서 찾을 수 있게 연결. 실험 결과를 지어내지 않음.
6. **커밋/확인:** 텍스트 자료만 업로드한 뒤 GitHub 파일 존재와 링크·변경 범위를 확인. 이미지/폰트/원저작 강의 PDF 원본은 게시하지 않음.

## 등록 시 사용하는 작은 카드

| 필드 | 반드시 남길 것 |
|---|---|
| 자료 | ID·수집 날짜·출처·원본 링크 확인 수준 |
| 관찰 | 보이는 타이포/색/형태/질감/레이아웃/정보구조 |
| 사용자 평가 | 좋아함/싫어함/부분 선호/미평가를 **속성별로** |
| 해석 | 매력의 원인 가설과 사용하기 어려운 과제 |
| 위험 | 가독성·접근성·기능·오류·매체·저작권/라이선스 |
| 연결 | 기존 사례 및 FOUND/Pattern/Style과 연결 |
| 검증 | 정적 문서·브라우저·사용자 실험·전문 검증 중 무엇을 실제 수행했나 |

## 강의·학술 자료일 때

- 문헌의 원 주장과 슬라이드·페이지를 먼저 정확하게 기록하고, 외부 근거는 **별도 열**에 기록한다.
- 교수 직함·출판기관만으로 개별 통계·효과 크기가 검증되었다고 하지 않는다.
- 공식 표준 소개 페이지를 읽었다면 **전문 전체를 검증한 것으로 표시하지 않는다**.
- 수치·심리학 법칙의 오용 위험은 [주장 검증 레지스터](foundations/CLAIM_VERIFICATION_REGISTER.md) 형식으로 따로 보존.
- 가능한 APA 제7판 참고문헌을 사용하되, 공개되지 않은 강의 PDF는 출처 URL을 지어내지 않는다.

## 실험은 선택적 후속

레퍼런스 등록은 **정적 분석 자체로 완료 가능**. 고위험 기능/안전 문제, 상충하는 실무 가설 또는 실제 사용자 선택을 확인해야 할 때만 최소 실험을 계획한다. 미수행은 NOT RUN. 사용자 승인 없이 범용 지침 개정·웹앱 수정·배포 금지.
