## 2. 인간중심 디자인·사용성의 개념

### 2.1 맥락, 사용자 참여, 반복

- [LECTURE, pp. 3–5] 여러 화면에 흩어진 EMR 정보, 읽기 어려운 환자교육 웹페이지, 불확실한 저장 상태, 행동 지침이 부족한 기기 경고를 문제 사례로 제시한다. 사용자의 특성·목표·필요·환경을 설계에 반영하고 사용자 참여를 통해 반복 개선하도록 소개한다.
- [STANDARD-ABSTRACT] ISO 9241-210:2019는 컴퓨터 기반 인터랙티브 시스템의 생명주기 전반의 인간중심 설계 원칙·활동을 다룬다. ISO 공식 사이트에서 **표준 범위·현행 여부**를 확인했지만 유료 전문 조항을 모두 검토하지는 않았다.
- [AI-HYP] 디자인을 시작할 때 사용할 사용자의 과업과 작업 환경(소음, 시간 압박, 장비, 숙련도, 이동 등)을 명시하는 것이 시각 스타일을 먼저 결정하는 것보다 재작업을 줄일 가능성이 있다. 아직 사용자 시험은 없다.

### 2.2 UI와 UX는 연결되지만 평가 범위가 다르다

- [LECTURE, p. 7] UX는 사용 전·중·후에 형성되는 경험이고, UI는 화면·버튼·메뉴·입력란·소리 등의 구체적 접점이다. 예약 버튼을 찾았지만 **예약이 완료되었는지는 모르는** 예시로 양자의 차이를 설명한다.
- [LECTURE, pp. 9–10] 정보구조(IA)는 정보를 묶고 탐색하게 하는 체계, 사용 흐름(User Flow)은 목표 달성 경로, 상호작용(Interaction)은 조작에 대한 반응과 상태 변화, GUI는 정보를 시각적으로 전달하는 형태·정보 위계·브랜드 표현이다.
- [AI-HYP] 따라서 사용자가 조작할 수 있는 예쁜 카드 하나만 만든 경우, 데이터 저장·완료 확인·되돌리기·복구를 확인하지 않았다면 좋은 UX라고 판정할 수 없다.

### 2.3 사용성을 나누어 측정한다

- [LECTURE, p. 25] 사용성은 **특정 사용자가 특정 환경에서 목표를 효과적·효율적·만족스럽게 달성**하는 정도. 예시는 복용할 약 확인하기.
- [STANDARD-ABSTRACT] ISO 9241-11:2018은 사용성을 사용 결과로 보는 정의·개념·적용 틀을 제시한다. 공식 요약은 확인했지만 유료 전문 전체는 미열람.
- [AI-HYP] 측정 예: **효과성**은 과업 성공·실수 없이 완료한 정도; **효율성**은 수행 시간·재시도·단계·도움 필요 여부; **만족도**는 인터뷰·SUS 등 주관적 경험. **임상 안전성**은 이 세 축과 별도로 중요 오류를 평가한다.

## 3. 심리학적 원리 10개: 강의 내용과 적용 경계

|---|---|---|
| Jacob’s law | 사용자에게 익숙한 메뉴·내비게이션 관례인가? | 낯선 전문 업무에서 무조건 대중적 관습만 따르는 것은 부적절할 수 있음 |
| Fitts’s law | 선택 대상의 크기·거리·자주 쓰는 행동 위치가 적절한가? | 터치·마우스·키보드·보조기기 등 다른 상호작용 환경을 통제해야 함 |

| Hick’s law | 선택지의 구조·복잡성이 의사결정을 어렵게 하는가? | 무조건 단계를 쪼개면 흐름 단절·반복 클릭이 늘어날 수 있음 |

| Peak-end rule | 핵심 순간과 마지막 피드백이 명확한가? | 실패를 감정적인 성공 화면으로 가리는 데 쓰면 안 됨 |
| Aesthetic-usability effect | 미감과 사용성에 대한 인식이 실제 사용과 다른가? | 선호도 점수를 과업 성공/오류가 적다는 증거로 오용 금지 |
| von Restorff effect | 꼭 강조해야 하는 정보가 구별되는가? | 모든 요소에 강조를 주면 정보 위계가 무너짐 |
| Tesler’s law | 불가피한 복잡성을 사용자 대신 시스템이 처리할 수 있는가? | 전문적으로 꼭 필요한 통제·근거까지 가리면 안 됨 |
| Doherty threshold | 인터랙션이 즉시 반응·상태를 보여주는가? | 강의의 0.4초를 모든 기기·네트워크·작업의 절대 합격선으로 채택하지 않음 |

## 5. 간호기술·환자 안전과 사용성

[LECTURE, pp. 25–27]는 작은 입력 오류와 상태 미인지가 환자 안전으로 연결될 수 있음을 사례로 제시한다.

| 교안에 나타난 오류 사례 | 검토할 설계 조건 [AI-HYP] | 확인할 실제 결과 |
|---|---|---|
| 다른 환자 기록에 입력 | 현재 환자 식별 정보·작업 대상 일관성 | 올바른 환자에게 기록했나? |
| 잘못된 수치 단위 | 단위 표시·허용 범위·환산/오류 경고 | 잘못된 단위 입력이 예방·감지됐나? |
| 경고를 반복 무시 | 위험도별 신호·구체적 다음 행동 | 경고를 이해하고 적절히 대응했나? |
| 저장 전 화면 이탈 | 실제 자동/임시저장·미저장 경고·복원 | 입력이 보존·복원됐나? |

- [OFFICIAL] FDA(2026-08-03)의 의료기기 인간공학·사용성 엔지니어링 지침은 사용자·사용·환경에 따른 사용 관련 위해를 줄이고 안전/효과성을 개선하도록 권고한다. **이는 규제 대상 의료기기 지침**이며, 모든 일반 간호정보 웹앱이 동일 법적 범위라는 뜻은 아니다.
- [LECTURE p. 27] 사용자 과업 관찰·문제 수정·재평가 및 SUS 설문 예시를 소개한다.
- [RESEARCH] SUS는 Brooke(1996)가 제안한 **10문항 주관적 사용성 척도**로, 성공률·업무 오류·임상 위해의 직접 측정 도구가 아니다. 교안에 보이는 질문은 **전체 SUS의 일부 예시**다.
- [AI-HYP] 실제 위험 기반 평가에서는 사용자 관찰·오류 빈도·성공률·시간·만족도를 따로 측정하며, 고위험 오류가 있으면 평균 미적 평가가 높아도 합격시키지 않는다.

## 6. 디자인씽킹: 해결책 전에 문제를 확인

[LECTURE pp. 28–29] 공감(확산)→문제정의(수렴)→아이디어(확산)→시제품(수렴)→테스트의 5단계를 소개한다. 이는 문제 해결을 위한 수업 모델이지, 모든 프로젝트에 동일한 다섯 번의 산출물을 강제하는 법률이나 국제표준은 아니다.

**가벼운 적용 [AI-HYP]**
1. 사용자의 현재 목표·곤란·환경 기록
2. 실패 가능한 중요한 과업 하나 정의
3. 조형과 구조의 대안 몇 개 중 목적에 맞는 안 선정
4. 작은 실행 가능한 예시를 만들되, 완료·오류·저장·복원 상태까지 고려
5. 관찰을 통해 원인이 지침/구현/콘텐츠/환경/개인 선호 중 무엇인지 분류

| 테스트 지표·증거 | §6 위험별 검증·보고 | [사용성 평가 카드](USABILITY_EVALUATION_CARD.md)로 별도 도구화 |
| 의료 전문 안전 계약 | 전문 기준 우선하는 우선순위 | FDA/기관/현장 계약 별도, 범용 지침으로 포섭 금지 |

**따라서 현 단계에서 범용 v1.3 개정은 권고하지 않는다.** 먼저 기존 규칙이 다루지 않는 실제 실패가 있는지 연구하고, 필요할 때만 개정 후보를 올린다. 지침의 정식 개정은 사용자 승인 사항이다.
