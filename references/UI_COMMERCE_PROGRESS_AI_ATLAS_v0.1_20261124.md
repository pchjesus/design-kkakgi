## 1. SRC-32 — 할인 표현: 가치 비교와 구매 압박은 다르다

| # | 화면 표기 | [OBS] 가시적 표현·정보 | 적용 목적과 반례 [AI-HYP] |
|---|---|---|---|
| 01 | 취소선 가격 / Strikethrough | 옛 가격 취소선, 50%, 새 가격 및 파란 선택 테두리 | 가격 차이를 즉시 비교. '정가'가 현실적인 기준인지 기간·근거 확인 필요 |
| 02 | 할인율 배지 / Discount badge | 주황색 패치에 30% 표시 | 축소 화면에서도 프로모션 발견. 실질 절감액·조건을 가릴 위험 |
| 03 | 마감 타이머 / Countdown | 남은 시간 숫자 | 진짜 종료시각이 있을 때만. 자동 리셋·허위 긴급성은 기만 |
| 04 | 쿠폰 받기 / Coupon | 3,000원 쿠폰, 받기 인터랙션처럼 표시 | 발급과 실제 적용을 구분, 최소 주문액·유효기간 안내 |
| 05 | 묶음 할인 / Bundle deal | 두 품목, 1+1 배지 | 수량·단위당 가격과 실제 필요량 확인 |
| 06 | 재고 표시 / Low stock | '5개 남았어요'와 빨간 게이지 | 사실 기반 재고일 때만, 범위·갱신 시각과 연결 |
| 07 | 최저가 표시 / Lowest price | 최근 30일 최저가처럼 보이는 작은 텍스트와 가격 | 비교기간·비교대상·제외 조건 명확화 |
| 08 | 적립금 / Reward points | 코인과 +390P | 즉시할인 아닌 후속 혜택, 사용 한도·소멸 등 분리 |
| 09 | 무료배송 바 / Free shipping bar | 3,000원 더 담으면 무료배송, 진행 막대 | 실제 배송비·추가 지출의 가치 균형, 장바구니 상태와 동기화 |

**[OBS] 카드뉴스 연출:** 밝은 회색/백색 표면, 3×3 카드를 동일한 비례로 배열, 제목에서 파랑 강조·검정 본문, 카드 하단 숫자와 한영 이중 레이블. 첫 카드만 파란 테두리로 시선 시작점을 만든다.

**[AI-HYP] 장점:** 단일 화면에서 9개 전술을 병렬 훑어보기 좋다. **한계:** 한 카드의 사례 글자는 모바일에서 작고, 금융·시간·재고·쿠폰 권리를 단일 '할인'으로 평탄화해 실제 적용 조건을 전달하지 못한다. 관성적인 9칸 카드 템플릿은 자료의 범주 차이를 감출 수 있다.

**[OFFICIAL]** 캐나다 Competition Bureau의 가짜 긴급성 안내와 미국 FTC 다크패턴 자료는 근거 없는 카운트다운·재고 제한·가격 인상을 경고한다. 이 화면의 실제 사이트가 위법하다는 주장은 아니다.

## 2. SRC-33 — '진행'이라는 말 아래 서로 다른 데이터 계약

| # | 화면 표기 | 실제 나타내려는 상태 | 설계·검증에서 구분할 것 |
|---|---|---|---|
| 01 | 단계 표시 / Step indicator | 정해진 단계 중 현재 단계 | 단계별 완료/현재/미착수, 중간 단계 생략·되돌림 |
| 02 | 진행 바 / Progress bar | 연속값으로 산정되는 수행량 (화면 예: 업로드 99%) | 측정 가능한 값인지; 불명확하면 거짓 퍼센트 금지 |
| 03 | 원형 진행 / Progress ring | 바와 같은 진행량을 원형으로 표현 (화면 예: 8/10) | 형상 차이가 데이터 의미 차이는 아님; 숫자 동반 |
| 04 | 타임라인 / Timeline | 사건의 순서와 상태·시간 | 역사적 이벤트와 미래 계획, 누락/지연 구분 |
| 05 | 체크리스트 / Checklist | 개별 항목의 체크 여부 | 사용자가 체크한 것과 서버 검증·승인된 것 분리 |
| 06 | 페이지 점 / Page dots | 여러 화면/슬라이드 중 현재 위치 | **작업 진행률이 아니라 탐색 위치**; 이전/다음 조작 가능해야 함 |
| 07 | 퍼센트 숫자 / Percentage | 진행 비율을 문자로 표현 (화면 예: 72%) | 분모·측정법, 수치 실시간성; 숫자만으로 의미 전달 부족 |
| 08 | 남은 시간 / Time left | 도착 예상 4분처럼 예측된 시간 | 정확한 시간 계측인지 ETA 추정인지 라벨에 드러내기 |
| 09 | 완료 표시 / Success state | 특정 업무가 성공했다고 알림 (화면 예: 예약 완료) | 요청/접수/승인/이행을 혼동하거나 조기 완료 표시 금지 |

**[OBS] 시각 표현:** 같은 3×3 카드 구조, 파란 수치·점·막대와 백색 배경, 검정 제목과 영문 보조 제목. 아이콘이 동일한 파랑이어도 정보의 시간축·분모·행동 수준은 서로 다르다.

**[AI-HYP] 분류:** (1) 정량 진행 02·03·07, (2) 절차 단계 01, (3) 이력 04, (4) 사용자 체크 05, (5) 탐색 위치 06, (6) 예측 시간 08, (7) 실제 처리 결과 09. 하나의 Progress 컴포넌트로 통일할 문제가 아니다. 완료는 진행률 100%와 같은 말도 아니다.

**[OFFICIAL]** WAI-ARIA 1.2는 값을 알 수 없는 progressbar에 `aria-valuenow`를 억지로 주지 않도록 하며, W3C의 ARIA25 기법은 진행값 속성이 자동으로 실시간 음성 안내되는 것은 아니므로 필요 시 live-region 상태 메시지를 고려하도록 설명한다. 표지·색과 숫자를 함께 쓰고, 단순 장식의 파란 막대가 상태 정확성을 대체하지 않게 한다.

**연결:** [인디케이터 아틀라스](MOTION_INDICATOR_ATLAS_v0.1_20261105.md) · [SRC-17 완료 피드백](UI_MOTION_BEHAVIOR_ADDENDUM_v0.1_20261108.md) · [SRC-27 스크롤 진행 vs 데이터 로딩](UI_SCROLL_EFFECTS_ATLAS_v0.1_20261117.md).

## 3. SRC-34 — AI 응답 UI: 사용자 행위, 출처, 생성 상태를 분해

| # | 화면 표기 | 기능·데이터 의미 | 필요한 예외/정확성 |
|---|---|---|---|
| 01 | 다시 생성 / Regenerate | 기존 요청에 대해 새 응답 버전 요청 | 기존 답변 보존·버전 비교·과금/지연·재시도 실패 |
| 02 | 복사 / Copy | 선택 답변 텍스트를 클립보드에 복사 | 실제 복사 성공 여부·서식·개인정보/숨겨진 데이터 제외 |
| 03 | 좋아요, 싫어요 / Feedback | 사용자 피드백 입력 | 제출/철회 상태, 평가의 용도와 영향 과장 금지 |
| 04 | 출처 / Citations | 답변 근거 자료로 이동·검토 | 링크가 실제 주장을 뒷받침하는지; 출처 표시가 정확성 보증은 아님 |
| 05 | 이어 묻기 칩 / Follow-up chips | 관련 후속 질문을 제안·선택 | 사용자가 직접 선택, 제안의 출처/정확성, 낯선 질문 자동 제출 금지 |
| 06 | 멈춤 버튼 / Stop | 진행 중 생성 또는 출력 중단 요청 | 중단 요청과 서버 처리 완료의 차이, 부분 답변 상태 |
| 07 | 스트리밍 / Streaming | 내용을 점진적으로 화면에 출력 | 전송/렌더링 방식이지 추론의 질이나 완결성의 증거가 아님 |
| 08 | 생각 중 표시 / Thinking | 처리 중임을 보여주는 상태 메시지 | 실제 내부 추론 내용 공개/정확성 보증으로 오인 금지; 침묵·중단·오류 대응 |
| 09 | 질문 수정 / Edit prompt | 사용자 입력을 고쳐 다시 요청 | 대화 분기와 기존 결과 보존, 이전 문맥/첨부·재전송 경고 |

**[OBS] 연출:** 상단에 Instagram 메시지 알림 오버레이가 커다랗게 놓여 있고, 3×3 패턴 설명은 아래에 배치. 이 알림은 카드뉴스 예시의 일부로 단정할 수 없다. 각 예시는 매우 작으므로 실제 컨트롤 크기·상태 동작·스크린리더 정보를 판독·검증하지 못함.

**[AI-HYP] 3층 모델:** (A) 결과 조작: Regenerate/Copy/Edit, (B) 신뢰·대화: Feedback/Citations/Follow-up, (C) 처리 상태/사용자 제어: Stop/Streaming/Thinking. 실제 앱 설계에서는 작업이 가능한 시점, 결과의 버전과 상호작용 후 상태를 먼저 정하고 버튼 형태는 그 뒤에 선택해야 한다. 'Streaming'과 'Thinking'은 같은 것도 아니고, 항상 UI 버튼이어야 하는 것도 아니다.

**적용과 비판:** AI 교육/검색/업무 앱에서 응답 검증과 수정·복구 권한이 중요하다. 의료·투자 등에서 출처 배지는 전문적 검증을 대체하지 않으며, 출처 없는 AI 추정에는 그 상태를 드러내야 한다. 정돈된 9칸 레퍼런스처럼 모든 행동을 나란히 전시하면 실제 화면의 주요 행동·보조 행동 위계가 무너질 수 있다.

**연결:** [SRC-12 로딩·스트리밍](UI_PATTERN_FIELD_ATLAS_v0.1_20261105.md), [SRC-30 입력·오류](UI_INPUT_DISTINCTIONS_ATLAS_v0.1_20261119.md), [범용 지침의 상태·출처·피드백 계약](../guidelines/universal/Universal_Visual_Design_UI_UX_Guidelines_v1.3.md).

## 4. 세 자료의 공통 시각언어와 한계

- **[OBS]** 회백색 톤+흰 카드+선명한 파랑 강조+검정 제목+작은 영문 번역을 반복. 주제별 학습 자료로서 구성을 일관되게 유지하며, 초보자에게 명칭을 소개하는 형식으로 기능.
- **[AI-HYP]** 그러나 같은 3×3 카드 형식은 개념 위계 차이(시각 효과/입력 동작/데이터 상태/비윤리적 마케팅 등)를 평면화한다. '모든 디자인에 카드 9개' 식의 범용 규칙은 [SRC-31 모던 UI 관습의 한계](MODERN_UI_CONVENTIONS_CRITIQUE_v0.1_20261119.md)와 충돌.
- **[USER]** 직전 3장에 대한 포괄적 '다 괜찮음' 외에 각 카드의 미적 우열·선호 이유·실사용 만족도는 확인되지 않았다. 새로운 2장에 대해서는 '레퍼런스 더 가져왔다, 다 반영'이라는 **분석·등록 요청**이 확인된 것이지 개별 호감 순위가 아님.
