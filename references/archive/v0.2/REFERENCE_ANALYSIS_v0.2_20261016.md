## 0. 이 분석이 의미하는 것과 의미하지 않는 것

- **관찰**은 캡처에서 실제로 볼 수 있는 색·위치·형태·문구·도표 구조이다.
- **해석/전용 가능한 원칙**은 관찰에 근거한 가설이지, 실험으로 입증된 사용성 개선이 아니다.
- **우려**는 잠재적 위험이다. 정적인 JPG/PNG만으로 접근성·기능·반응형 FAIL을 확정하지 않는다.
- **선호 신호**는 사용자가 이미지를 수집했다는 사실뿐이다. 화면의 **모든 요소를 좋아한다**거나 특정 색을 **모든 프로젝트의 기본값으로 선호한다**는 뜻이 아니다.
- 외부 출처/제작자/정확한 폰트/저작권은 대부분 미확인이다. 사용자가 제공한 Behance 링크(`https://www.behance.net/gallery/237734473/Dieter-Rams-Collection`)는 관련 후보지만 **어느 이미지가 그 링크의 작품인지 개별적으로 검증되지 않았다.** 전체 20장에 일괄 지정하지 않는다.
- 서로 다른 캡처가 같은 프로젝트의 다른 장면일 수 있다. 예컨대 REF-004/005(1Doc), REF-006/007(Switch 2), REF-012~014(꽃 서비스, 잠정)는 **독립된 취향 표본으로 중복 집계하지 않는다**.

- **관찰된 사실:** 포화 코발트 블루와 오렌지색 면의 대각선 대비, 제품 윤곽을 따라 그린 백색 선 도면, 우측 아래의 흰색 정사각형 다이얼, 작고 구체적인 제품 표기.

- **위험·오용 방지:** 비스듬히 배치된 설명 문구와 작은 다이얼 숫자는 판독성이 떨어질 수 있다. 포스터형 구도를 실제 설정 화면의 정렬 방식으로 그대로 옮기면 조작성에 불리하다.
- **적용 후보:** 제품 소개·산업디자인 아카이브·교육용 기기 설명 / **직접 전용 비추천:** 시간·약물·수치를 정확히 입력해야 하는 고위험 UI

## 7. 이미지 폐기 전 남겨야 할 지식과 한계

### 7.1 기록할 필드

- `reference_id` (고정 ID), `original_upload_name`, `sha256` (일치 검증용), `source_url`, `creator`, `license_status`.
- `observed`와 `interpretation`을 반드시 분리한다.
- `principle`은 ‘무엇을 언제 어떻게 적용하나’의 조건문으로 작성한다.
- `risk`, `avoid`, `unknown`은 요약 삭제 시에도 남긴다.
- 태그는 **매체/역할/형태/색채/정보 밀도**와 같은 여러 축을 허용한다.

### 7.2 기본 이미지 수명주기

1. 사용자 첨부 ZIP을 **임시 영역**에서 풀고, 이미지 수와 해시를 검증한다.
2. 이미지별 관찰과 적용/비적용 조건을 기록하고 분석 문서를 사람이 검토한다.
3. 출처 불명 항목은 `UNVERIFIED`로 남긴다. 원본 링크를 실제 확인하지 않고 추정으로 채우지 않는다.
4. 분석 품질을 수락한 경우 이미지를 GitHub에 커밋하지 않고 **Markdown/JSON/CSV만 업로드**한다.
5. 임시 이미지 제거는 **작업 영역에서만** 수행한다. ChatGPT 대화/첨부/백업까지 영구 삭제했다고 주장하지 않는다.
6. 삭제 후에는 원본 이미지에 없는 디테일을 미래에 재검증할 수 없음을 표시한다. 중요 사례에 대해 원본 외부 링크를 별도 보존하도록 권장한다.
7. 이미 Git 이력에 넣었다가 삭제하는 방식은 저장소 용량/저작권 관리에 적합하지 않다. 원본 이미지를 애초에 커밋하지 않는다.
