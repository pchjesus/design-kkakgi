# KRDS 레이아웃 아틀라스 v1.0 — 페이지 구조를 먼저 설계하기

> **범위:** 2026-10-20 확인한 KRDS 공식 [레이아웃 디자인 스타일](https://www.krds.go.kr/html/site/style/style_05.html)에서 직접 근거를 읽어 정리했다. 아래 **A. 공식 값**과 **B. 파생 설계 후보**를 혼동하지 않는다. 이 문서는 범용 지침 v1.2 DRAFT의 개정본이 아니다.

## A. KRDS에서 확인한 설계 기준

### A-1. 그리드 구성요소

| 요소 | KRDS의 역할 | 설계 판단 |
|---|---|---|
| Screen margin | 화면 가장자리와 콘텐츠 사이 여백 | 좁은 화면의 터치 안전·읽기 여백 |
| Column | 수직 배치 구획 | 같은 화면 안에서 그리드의 일관성 유지 |
| Gutter | 칼럼 사이 간격 | 정보 군집과 요소 구분 |
| Breakpoint | 레이아웃 변화가 일어나는 화면 너비 | 장치명이 아닌 가용 공간·과업으로 실제 조정 |

**공식 확장형 범위/권고:**

| 구간 | 시작 뷰포트 | 칼럼 적정~최대 | 가터 최소~적정 | 최소 화면 가장자리 여백 |
|---|---:|---:|---:|---:|
| xsmall | 359px 이하 | 4–6 | 16px | 16px |
| small | 360px 이상 | 4–6 | 16px | 16px |
| medium | 768px 이상 | 8–12 | 16–24px | 24px |
| large | 1024px 이상 | 12–16 | 16–24px | 24px |
| xlarge | 1280px 이상 | 12–16 | 16–24px | 24px |
| xxlarge | 1440px 이상 | 12–16 | 16–24px | 24px |

**공식 표준형 예시:** small/medium/large/xlarge 4단계에 각각 4/8/12/12 칼럼과 16/16/24/24px 가터를 사용한다. 표준형 콘텐츠는 최대 **1200px**으로 제한한다. 이 값은 **KRDS 표준형**의 값이지 모든 웹사이트의 전역 최대 폭이 아니다. 확장형은 필요에 따라 가변 콘텐츠 너비를 택할 수 있다.

### A-2. 정보가 많아지면 서브페이지 영역을 나눈다

공식 서브페이지의 주요 영역은 **Header → Left menu(선택) + Main contents + Right menu(선택) → Footer**다. 좌측 메뉴는 깊은 정보 구조 탐색, 우측은 본문 내 탐색·빠른 도움에 적합하다. 양측을 동시에 쓸 때는 작은 화면의 본문 가독성을 우선한다.

### A-3. 간격 계층

- KRDS는 주로 **8pt 그리드**를 기본으로 하되 2·4·10 등 미세 조정 단위도 허용한다.
- Gap(요소 사이), Padding(요소 내부), 반응형 간격의 역할을 구분한다.
- 공식 페이지 예시: 카드 목록 gap-7=24px, 입력 컨트롤 가로 간격 gap-5=16px, 입력 필드 내부 간격 gap-3=8px. **필요 시 실제 토큰 값과 최신 문서 재확인.**
- 정보 구조의 의미 없이 여백을 무조건 크게 늘리거나, 공간이 남는다는 이유만으로 카드 수를 늘리지 않는다.

## B. 페이지 아키타입 — KRDS에서 파생한 **설계 후보** (공식 템플릿명 아님)

| 후보 | 영역 개념 | 적합한 과업 | 부적합·위험 | 같이 볼 공식 패턴 |
|---|---|---|---|---|
| L1. 랜딩/허브 | 핵심 가치·주요 작업 진입 → 중요 공지 → 카테고리 → 보조 정보 | 첫 방문·탐색 시작점 | 홍보 히어로가 업무 진입을 밀어내는 경우 | [방문](https://www.krds.go.kr/html/site/service/service_01_01.html) |
| L2. 목록/탐색 | 검색·필터·정렬 ↔ 결과 목록/표 → 상세 | 다수 아이템 조회·비교 | 필터를 지나치게 숨겨 조건 확인 불가 | [목록 탐색](https://www.krds.go.kr/html/site/global/global_04.html), [필터링·정렬](https://www.krds.go.kr/html/site/global/global_10.html) |
| L3. 상세/문서 | 제목·요약·메타 → 본문 → 내부 목차(선택) → 행동 | 정책·문서·지식·설명 페이지 | 짧은 글에도 과도한 양측 내비게이션 | [상세 정보](https://www.krds.go.kr/html/site/global/global_06.html) |
| L4. 작업/입력 | 현재 단계·목적 → 입력 → 검토 → 완료 상태 | 신청·업무 등록·평가 기록 | 높은 정보 밀도와 불필요한 단계 분리 | [신청](https://www.krds.go.kr/html/site/service/service_04_01.html), [입력폼](https://www.krds.go.kr/html/site/global/global_08.html) |
| L5. 지식/업무 워크스페이스 | 전역 탐색 + 좌측 트리(선택) + 집중 작업영역 + 우측 도움/맥락(선택) | 반복 탐색·업무·학습 | 좁은 화면에서 본문이 지나치게 압축 | [서브페이지 레이아웃](https://www.krds.go.kr/html/site/style/style_05.html) |
| L6. 상태/결과 | 결과 요약 → 중요한 상태·오류 → 다음 행동/수정 → 상세 | 신청 결과·검증 결과·작업 알림 | 성공 배너만 두고 이후 행동 없음 | [오류](https://www.krds.go.kr/html/site/global/global_07.html), [확인](https://www.krds.go.kr/html/site/global/global_11.html) |

**주의:** 이것은 KRDS가 제공하는 이름이 아닌, 디자인 깎기에서 실험할 **아키타입 후보**다. 결과는 별도 시안 비교 전까지 **가설**로 기록한다.

## C. 다각화된 페이지를 만들기 위한 선택 프로토콜

1. **우선 사용자의 1차 과업**을 문장으로 적는다. (예: '정보 찾기', '기록 입력', '상태 비교', '이해하고 학습')
2. **정보량·작업 빈도·탐색 깊이·데이터 밀도**를 평가한다. 표현 목적보다 이용 흐름을 먼저 결정한다.
3. 후보를 **최소 두 가지** 제안한다. 예: L1 허브형 vs L5 업무형, L2 표중심 vs 카드중심. 한 가지 패턴으로 수렴하는 관성을 경계한다.
4. 각 후보의 **장점/단점/실패 조건**을 명시한다. 넓은 여백, 중심정렬, 카드 배치를 기본 정답으로 삼지 않는다.
5. 레이아웃이 결정된 뒤에 [컴포넌트 검색](COMPONENT_GUIDE.md), [토큰](TOKEN_GUIDE.md)과 타이포/색/모션 레퍼런스를 배합한다.
6. 320·390·768·1024·1440px 등 **실제로 테스트한 폭**을 명시하여 접근성과 가독성을 검증한다. KRDS 표준형은 xsmall 최적화 대상이 아니지만, 디자인 깎기의 제품이 320px을 지원한다면 별도 테스트할 수 있다.

## D. 빠른 UX 검토 질문

- 첫 화면에서 원하는 **행동**이 먼저 보이나, 장식이 먼저 보이나?
- 레이아웃이 중앙으로만 몰려 **가용 폭을 활용하지 못하는지**, 아니면 과도하게 펼쳐져 읽기 어려운지?
- 우측 공간이 비었다면 **맥락 도움/상세 정보**가 실제로 필요한지? 불필요한 패널을 억지로 만들지 않는다.
- 왼쪽 메뉴가 필요한 만큼 정보 구조가 깊은지? 단순한 페이지에서 두터운 내비게이션을 강제하지 않는다.
- 표와 카드 중 무엇이 사용자의 **비교 과업**에 실제로 더 적합한지?
- 모바일에서 세부 정보·메뉴·작업 흐름이 어떻게 **재배치**되는지?
