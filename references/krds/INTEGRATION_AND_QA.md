# KRDS v1.1.0 — 실제 프로젝트 통합·접근성·회귀 체크리스트

이 문서는 **디자인 레퍼런스**를 실제 동작 앱으로 옮길 때의 작업 계약이다. KRDS 예제를 저장해 둔 것만으로 설치·실행·접근성 적합성이 보장되는 것은 아니다.

## 1. 용도 결정 → 최소 통합

**탐색만 하는 경우** (디자인 깎기의 현재 용도)
1. `component_catalog.json`에서 컴포넌트를 찾아 공식 `html/code/*.html` 원본을 연다.
2. 관련 SCSS 하나와 필요시 `ui-script.js`의 특정 모듈을 확인한다.
3. 패턴의 적용 가능성, 한계, 전후 검증 방법만 기록한다.
4. 이 저장소에는 `node_modules`, KRDS 원본 이미지·폰트·전체 배포 번들을 추가하지 않는다.

**실제 앱에 쓰기로 승인된 경우**
1. 수정할 **대상 앱 저장소**에서 `npm install krds-uiux@1.1.0`처럼 패키지 버전을 고정하거나 검증 가능한 고정 참조를 설정한다.
2. 앱의 번들러 설정에 맞춰 필요한 CSS/JS를 로드한다. 로드 방식과 파일 존재는 앱 빌드에서 확인한다.
3. HTML **예제 조각**을 앱의 DOM/컴포넌트 구조에 맞게 이식한다. 예제 파일을 완성된 웹페이지라고 가정하지 않는다.
4. 기존 앱의 CSS 명명·초기화·이벤트와 충돌 검사 후, 지원 대상 브라우저에서 실제 테스트한다.
5. 서버 기능(업로드, 로그인, 인증, 개인정보 저장)은 UI와 분리해 설계한다. **예제 마크업은 인증/보안 기능이 아니다.**

## 2. 분석에서 확인된 통합 위험

| 주제 | 확인/예상 위험 | 검증·완화 |
|---|---|---|
| JS 초기화 | `ui-script.js`가 `DOMContentLoaded`에 여러 모듈을 한 번에 `init()` | SPA·React/Vue의 동적 삽입 시 초기화 여부, 중복 리스너/cleanup 확인 |
| CSS 에셋 | `resources/cdn/krds.min.css`는 외부 KRDS 절대 URL SVG 아이콘을 참조 | 오프라인·방화벽·개인정보 정책 환경에서 리소스 누락/외부 요청 검사 |
| CSS 경로 | `resources/css/`의 스타일은 상대 `img` URL을 사용 | 빌드 뒤 링크 깨짐/중복 경로 확인 |
| 폰트 | `resources/fonts/`에는 PretendardGOV WOFF/WOFF2 파일이 있음 | 폰트 로드 경로·라이선스·fallback·한글 줄바꿈 검사 |
| Swiper | 캐러셀용 플러그인 CSS/JS가 패키지에 있음 | 중복 버전, 모바일 제스처, 동작 중지, 키보드 테스트 |
| 조각 HTML | 일부 샘플은 스크립트/스타일 로더 없는 부분 마크업 | 최소 실행 페이지에 실제 삽입한 후 테스트 |
| 템플릿 접근성 | `skip_link` 앵커, 파일 선택 중첩 인터랙션 등 점검 지점 존재 | 예제를 복사하더라도 KWCAG/WCAG 적합 판정은 별도 |
| 정보 보호 | 로그인/자료 열람 화면만 구현해서 권한이 생기는 것은 아님 | 서버측 인가, 접근 제어, 이벤트 로깅, 민감정보 최소화 |

## 3. UI 적용 전후 체크 (기본 PASS/FAIL/NOT RUN/N/A)

- **정확성:** 사용자가 승인한 기존 화면·기능·상태·데이터·라우트가 보존되는가?
- **마크업:** label-for/id가 일치하고 ID가 중복되지 않는가? 표 헤더·제목 계층이 맞는가?
- **조작:** 마우스/키보드/터치 각각에서 활성화·닫기·ESC·Enter·Space가 적절한가?
- **포커스:** 모달/메뉴 개폐 시 포커스 이동·복귀가 되는가? focus 표시가 지워지지 않는가?
- **상태:** 오류·disabled·loading·success가 의미와 연결되고 색상만으로 표시되지 않는가?
- **반응형:** 320/390px 및 데스크톱에서 가로 넘침·클리핑·버튼 가림이 없는가?
- **텍스트 확대:** 200% 텍스트 확대 및 브라우저 줌에서 모든 탭/모달/리스트에 일관된가?
- **색상/대비:** 기본/hover/focus/error/고대비 모드에서 식별 가능한가?
- **동적 콘텐츠:** 탭·모달·오류·상태변화가 보조기기에 적절히 전달되는가?
- **성능:** 불필요한 번들·외부 이미지·폰트 요청, 중복 이벤트 리스너가 없는가?
- **보안:** 폼 검증은 서버에서 재검증하는가? 데이터 열람 권한은 서버에서 검사하는가?
- **회귀:** 저장·복원, 모달 재개방, 연속 탭 전환, 뒤로가기, 새로고침과 여러 뷰 재방문이 정상인가?

**검증 상태:** 위는 체크리스트이며, 샘플/대상 앱의 브라우저 실행이나 자동 접근성 테스트를 이 문서 작성 시점에 수행하지 않았다 (**NOT RUN**). 코드 정적 확인과 검증을 구별한다.

## 4. 의료·돌봄/개인정보 UI에 적용 시 추가

- 환자 식별이나 보호자/직원 역할 선택은 프런트엔드 입력만으로 인증·인가되지 않는다.
- 민감정보는 GitHub Pages/localStorage에 실제 값으로 저장하지 않는다. 테스트에는 가명·합성 데이터를 사용한다.
- 큰 글씨 모드, 쉬운 용어, 단계 구분, 오류 복구 등은 KRDS 원본과 별개로 실제 사용자를 대상으로 평가해야 한다.
- 위험 분류·임상 판단 등은 디자인 시스템이 검증할 수 없다. UI 예제의 존재를 임상적 검증으로 표현하지 않는다.

## 5. 이후 AI 작업의 실무 규칙

1. 원본과 앱의 **현재 브랜치/버전** 확인 → 기존 계약/동작 보존 목록 작성.
2. **문제 1개당 최소 파일**부터 읽기 → 변경 범위와 예상 회귀 위험 보고.
3. 독립 실험 또는 승인된 대상 앱에서 적용, 기존 프로젝트 자동 반영 금지.
4. 실제 수행한 정적/브라우저/실기기 검증을 구분해 기록한다.
5. 원본 업데이트는 `SOURCE_PROVENANCE.md`의 ZIP 해시/패키지 버전과 비교하고 **검토 후** 색인을 갱신한다. 최신 `main`을 v1.1.0과 동일하다고 가정하지 않는다.
