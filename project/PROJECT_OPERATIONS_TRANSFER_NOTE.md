# 프로젝트 운영 전달 메모 (GitHub 초기 구축 지원용, 정식 지침 대체 아님)

- 목표: 개인의 색채·미감을 재현하는 것이 아니라 소재·목적·이용자·매체에 맞게 디자인 판단 및 구현·검증 능력을 향상한다.
- 역할: **일반 ChatGPT 채팅**=향후 코드 제작·견본·분석·비교·지침 개정안, **Work**=이번 최초 GitHub Private 저장소 개설·파일 이관에 한정, **GitHub**=기준 자료·실험·버전 이력 저장, **사용자**=중요 UX·브랜드·지침 정식 승인.
- 현재 실험 사례: (1) MUL. 물컵 홍보 사이트 — 제품·홍보형 (2) SAI — 정보·콘텐츠형. (3) 작업형 웹앱은 추후 선정, 최초 초기화 시 새 견본을 만들지 않는다.
- 최신 시험 기준은 **범용 v1.2 DRAFT** 및 해당 빠른 실행 카드. 시뮬레이터의 특수 안전·교육 제약은 별도, 개별 프로젝트의 기존 기능·데이터·안전 계약이 우선.
- 실험 방법: 가설과 성공·실패 기준 명시 → 동일 내용/기능/조건 유지 → 실제 코드와 화면 제작 → 타이포·색상·레이아웃·반응형·접근성·모션·기능/상태 회귀 확인 → 개선 및 퇴보 비교 → 지침/구현/소재/평가 편향/렌더링 문제 구분 → 반복성·영향 큰 문제만 지침 개정 제안.
- 평가: 미관, 상황 적합성, 사용성/접근성, 기능·상태 정확성을 분리. 위험한 실패를 평균 점수로 상쇄하지 않는다. 검증 상태는 PASS/FAIL/NOT RUN/N/A.
- 권한: GitHub 배포/공개 전환, 기존 기능 삭제, 저장 구조 변경, 기존 브랜드 방향 교체, 지침 승인 및 정식 개정은 별도 확인 및 승인이 필요하다. 이번 요청은 **Private 저장소 초기화 및 파일 보존**만 승인 대상이다.
- 레퍼런스 원본 스크린샷: 임시 분석 → 시각적 관찰/제작자/원본 URL/한계 기록 → Git에는 텍스트 메타데이터만 남긴다. 추정한 사용자 취향을 범용 규칙으로 자동 채택하지 않는다.
- Work는 일회성 초기화 과정 이후 계속 백그라운드에서 디자인 작업을 수행하는 것으로 가정하지 않는다. 이후 일반 채팅에서 현재 GitHub를 재확인해 작업을 이어간다.
